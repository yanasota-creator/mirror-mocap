# Mirror Mocap PC版（Python トラッカー ＋ Unity）

Web版と同じ「内蔵カメラで体・顔・指を推定してVRMアバターを動かす」を、PCアプリとして動かす版です。

```
[カメラ] → tracker.py（Python / MediaPipe） --UDP 127.0.0.1:39540--> Unity（MirrorMocapReceiver.cs が VRM を動かす）
```

- **推定（AI）**：Python の `tracker.py` が担当します。体・顔・手の3つのAIをMediaPipe内部で並列に動かします
- **表示**：Unity が担当します。モデルの髪やスカートの揺れは、UniVRM の揺れもの機能がそのまま効きます
- **つなぎ方**：同じPCの中で、UDP（軽い通信方式）を使って1回あたり約2KBのデータを送ります

> **状態（2026-11-05時点）**：`tracker.py` は、この開発環境で動画ファイルを入力にして、送信まで動作確認済みです。
> Unity側の `MirrorMocapReceiver.cs` は、UniVRM 0.131 のソースコードと照らし合わせて確認し、Unityの代わりの簡易部品とのコンパイルが通ることを確認しています。**実際のUnityではまだ一度も動かしていません。** 下の「5. 動作確認チェックリスト」で確かめてください。

## かんたん起動（コマンドを打たない方法）
Python を入れたあと（https://www.python.org/downloads/ 、Windows ではインストール画面で「Add python.exe to PATH」にチェック）、次のファイルを**ダブルクリック**するだけで起動します。初回だけ、必要な部品を自動で入れます（数分）。

| 起動するもの | Windows | Mac |
|---|---|---|
| トラッカー（カメラ → Unity） | `tracker/start-windows.bat` | `tracker/start-mac.command` |
| ブリッジ（Web版 ⇄ VRChat・VSeeFace など） | `bridge/start-windows.bat` | `bridge/start-mac.command` |

- Windows で「WindowsによってPCが保護されました」と出たら「詳細情報」→「実行」を押します
- Mac で「開けません」と出たら、ファイルを右クリック →「開く」を選びます。それでも開かないときは、ターミナルで `chmod +x ` と入力してからファイルをドラッグして Enter を押します（実行してよいという印を付けるコマンドです）

以下は、コマンドで起動する場合の手順です。

## 1. トラッカー（Python）の準備

1. Python 3.10〜3.12 を入れる（https://www.python.org/downloads/ 。インストール時に「Add python.exe to PATH」にチェック）
2. このフォルダの `tracker` でターミナル（Windowsなら「コマンドプロンプト」）を開いて、必要な部品を入れる

```bash
pip install -r requirements.txt
```

3. 起動する（初回はAIモデル約20MBを自動でダウンロードします）

```bash
python tracker.py --preview
```

`--preview` を付けると、カメラ映像に推定した点を重ねた確認用の窓が出ます。q キーで終了です。

| オプション | 意味 |
|---|---|
| `--camera 1` | 2台目のカメラを使う |
| `--quality light` / `standard` / `high` | 軽量・標準・高精度（体のAIモデルの重さが変わる） |
| `--video 動画.mp4` | カメラの代わりに動画ファイルで試す |
| `--port 39540` | 送信先ポート（Unity側と合わせる） |

## 2. Unity の準備

1. Unity Hub から **Unity 6（6000.0 LTS）** か **2022.3 LTS** を入れ、「3D」テンプレートで新しいプロジェクトを作る
2. UniVRM（UnityでVRMを扱う公式の部品）を入れる
   - https://github.com/vrm-c/UniVRM/releases の最新版から **`VRM-…unitypackage`**（VRM 1.0用）をダウンロードする
   - Unity の画面にドラッグ＆ドロップして「Import」を押す
3. このフォルダの `unity/Assets/MirrorMocap` を、Unityプロジェクトの `Assets` の中にコピーする
4. 使いたい `.vrm` ファイルを Unity の `Assets` にドラッグする（自動でモデルに変換されます。VRM 0.x のモデルも VRM 1.0 に変換されます）
5. 変換されたモデルをシーン（Hierarchy）にドラッグする
6. シーンに置いたモデルを選び、Inspector の「Add Component」で **`MirrorMocapReceiver`** を追加する
7. 再生ボタン（▶）を押してから、`tracker.py` を起動する

## 3. 操作

| 操作 | 内容 |
|---|---|
| C キー | 正面リセット（まっすぐ座った姿勢を「正面」として記憶） |
| M キー | ミラー切り替え |
| 1〜5 キー | 表情（喜・怒・哀・驚・穏）。もう一度押すと戻る。0 キーで解除 |
| Inspector の項目 | ミラー・脚・なめらかさ・ぷるぷる・視線・体の位置（Move Body：左右に動く・しゃがむとアバターも移動）・喜怒哀驚の再現（Emotions）とその感度（Emotion Gain）を変更できる |

キーが効かない場合は、Inspector で `MirrorMocapReceiver` の右上の「⋮」メニューから「正面リセット」を選べます（キーは Unity の古い入力方式・新しい入力方式のどちらでも効きます）。

## 4. うまく動かないとき

| 症状 | 考えられる原因と対処 |
|---|---|
| Unity でモデルが動かない | Console に「UDP 39540 で待ち受け中」と出ているか確認する。tracker.py の `--port` と合わせる。ファイアウォールの許可画面が出たら許可する |
| 体は動くのに顔が動かない／表情が出ない | モデルが VRM 1.0 として読み込まれていない可能性。モデルに `Vrm10Instance` が付いているか確認する |
| 動きがモデルに反映されない（T字のまま） | モデルの Animator の「Controller」欄に何か入っていると、アニメーションが姿勢を上書きします。Controller を空（None）にする。Console に黄色い警告が出ていないかも確認する |
| 左右が逆 | Inspector の Mirror を切り替える |
| tracker.py が「カメラを開けません」 | `--camera 1` などに番号を変える。Zoom 等を閉じる |

上から順に確かめて、**ダメだった番号と、そのときの様子（できればスクリーンショット）と、Console の赤・黄色のメッセージ**を教えてください。そこから直します。

| # | やること | うまくいったときの様子 |
|---|---|---|
| 1 | ▶ を押す | Console に「UDP 39540 で待ち受け中」と出る。赤いエラーが出ない |
| 2 | `python tracker.py --preview` を起動 | 確認用の窓に、体・顔・手の点が重なって表示される |
| 3 | まっすぐ座って C キー（正面リセット） | アバターがまっすぐ前を向く |
| 4 | 右手を上げる（ミラーON） | 画面の中で、自分と同じ側（鏡と同じ）の手が上がる |
| 5 | ひじを曲げる・手を前に出す | 腕が逆向き・ねじれた向きに曲がらない |
| 6 | 体を左右に傾ける・ひねる | 上半身が同じ向きに傾く・ひねる |
| 7 | 首をかしげる・左右を向く | 頭が同じ向きに動く（上下が逆になったりしない） |
| 8 | まばたき・口を開ける・笑う・片目だけ閉じる（ウインク） | アバターも同じ表情になる |
| 8b | 眉を寄せる／目を見開いて眉を上げる／眉尻と口角を下げる | 怒り／驚き／悲しみの表情になる（笑っているときに怒り顔にならないこと） |
| 9 | 目だけ左右・上下に動かす | アバターの目も同じ向きに動く |
| 10 | 手を開く・グーにする・ピース | 指が同じ形になる（手首がねじれない） |
| 11 | 手で口を隠す | 頭の向きと口の形がそのまま保たれる |
| 12 | 1〜5 キーを押す | 表情が変わる（0 キーで戻る） |
| 13 | Inspector で Move Body をオンにして、C キーのあと左右に動く | アバターも同じ向きに動く |

## 6. 外部連携（Web版 → VRChat・VSeeFace など）

ブラウザは VRChat などが使う通信（UDP）を直接送れないので、PCで小さな中継プログラム `bridge/bridge.py` を動かします。Python があれば、追加のインストールは要りません。

```
[Web版] --WebSocket--> bridge.py --OSC--> VSeeFace / Warudo / VNyan など（VMC、ポート 39539）
                                   └--OSC--> VRChat（ポート 9000）
```

1. `native/bridge` フォルダでコマンドプロンプトを開き、起動する

```bash
python bridge.py
```

2. Web版の「外部連携」→「PCブリッジに送信」をオンにする。「接続中」と出れば送れています（ブラウザに「ローカルネットワークへのアクセス」の許可を聞かれたら「許可」）
   - **index.html をファイルから開いている場合だけ**、「接続コード」の欄が出ます。ブリッジを起動した画面の「接続コード: ABCD-EFGH」の8文字を入れてください（1回入れればブラウザが覚えます。コードは `bridge-code.txt` に保存され、起動するたびに変わったりはしません）
3. 受け取る側のアプリを設定する

| 送り先 | 設定 |
|---|---|
| VSeeFace | 設定 → 一般設定 →「OSC/VMCプロトコルで受信」をオン、ポート 39539 |
| Warudo / VNyan | VMC の受信（モーションキャプチャ → VMC）を追加して、ポート 39539 |
| VRChat | アクションメニュー → オプション → OSC を「有効」。**体のトラッカー（腰・胸・足・膝・ひじ）はVRモードのフルトラッキングとして使われます**（デスクトップモードでは体には反映されません）。チャットボックスへの文字送信はデスクトップでも使えます |

| オプション | 意味 |
|---|---|
| `--no-vmc` / `--no-vrchat` | どちらかだけに送る |
| `--vmc 192.168.1.20:39539` | 別のPCの受信アプリに送る |
| `--vmc-in 39542` | VMC を受け取るポート（初期値 39542、`0` でオフ） |
| `--vmc-in-lan` | スマホなど、同じWi-Fiのほかの機器からの VMC も受け取る |
| `--allow-origin https://example.com` | Web版を自分で別の場所に置いたとき、そのページからの接続を許可する |

#### ブリッジの安全対策
- つながれるのは、公開版のページと、このPCの中のページ（localhost）だけです。ほかのWebサイトを開いていても、そのサイトからアバターを動かしたり、VRChat のチャットに書き込んだりはできません
- ファイルから開いたページは、どのサイトのものか区別できないので、接続コードが必要です（ほかのサイトは、仕切った小窓を使うと同じ見た目でつないでこられるため）。コードを5回続けて間違えると、1分間ファイルからの接続を止めます
- 他人に知られたと思ったら `bridge-code.txt` を消してブリッジを起動し直すと、新しいコードになります
- `--vmc-in-lan` を付けたときは、同じ Wi-Fi の機器なら誰でもアバターを動かすデータを送れます。家のネットワークなど、信頼できる場所でだけ使ってください

### OBS に背景なしでアバターを映す（OBS用ビューア）
グリーンバックを使わずに、アバターだけを配信画面に重ねられます。

1. ブリッジを起動して、ふだんどおり Web版を開き「PCブリッジに送信」をオンにする（カメラで動かす側）
2. Web版の「外部連携」にある OBS 用 URL を「コピー」する（`https://yanasota-creator.github.io/mirror-mocap/?viewer`）
3. OBS の「ソース」→「＋」→「ブラウザ」で、URL に貼り付け、幅 1280・高さ 720 などにする
4. OBS の画面に、背景が透明なアバターが出る。動きと表情は 1. のページから届く

- URL の最後に `&view=full`（全身）・`&view=face`（顔）を付けると視点を変えられます。モデルは 1. のページと同じものになります（自分のVRMは、OBS の中から読めないので最初のモデルになります）
- 映るのは姿勢と表情だけです（小物やエフェクトは映りません）

### VRChat でできること（まとめ）
| 機能 | Web版の設定 | 備考 |
|---|---|---|
| 体のトラッカー（腰・胸・足・膝・ひじ） | 「PCブリッジに送信」 | VRモードのフルトラッキングとして使われる |
| チャットボックス | 「吹き出し・チャット」 | デスクトップでも使える。音声認識の字幕も送れる |
| 表情 | 「VRChat：表情ボタンで送るパラメータ名」 | アバターに表情用の int パラメータがあるとき（名前と番号の意味はアバターによる） |
| ジャンプ | 「VRChat：両手を上げるとジャンプ」 | 両手を頭より上に上げる |

### ほかのモーションキャプチャの動きで Web版のアバターを動かす（VMC受信）
mocopi や、iPhone の顔トラッキングアプリ（Waidayo など）は VMC で動きを送れます。

1. `python bridge.py --vmc-in-lan` で起動する（スマホから送るときは `--vmc-in-lan` が必要。同じPCのアプリからなら付けなくてよい）
2. 送信アプリの送り先を「このPCのIPアドレス」・ポート **39542** にする（IPアドレスは Windows ならコマンドプロンプトで `ipconfig` を実行すると「IPv4 アドレス」に出ます）
3. Web版の「外部連携」→「外部トラッカーの動きで動かす（VMC受信）」をオンにする。「受信中：骨 ○本・表情 ○個」と出れば成功

送られてきた骨と表情だけを上書きするので、「顔は iPhone、体は内蔵カメラ」のような組み合わせもできます。

- **安全のため**、公開中のWeb版（`https://yanasota-creator.github.io`）と、このPCで開いたページからの接続だけを受け付けます。ほかのサイトが勝手にアバターを動かしたり、チャットボックスに書き込んだりはできません
- **確認済み**：開発環境で、Web版 → bridge.py → 受信テスト用プログラムまで、VMC（骨と表情）と VRChat（トラッカー、チャットボックス）のデータが正しい形式で届くことを確認しました。**実際の VSeeFace・Warudo・VRChat ではまだ試していません**
